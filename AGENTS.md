# VillaST

## What this is

Static website for a vacation rental (Rifugio Tavolara) in San Teodoro, Sardinia: marketing page
plus an integrated booking system with an admin dashboard. **No build step at deploy time** —
HTML5 + CSS3 + vanilla JS ES modules loaded from CDN, with Firebase (Firestore + Auth) as the only
backend. One generated file (`en/index.html`) is committed, never built in CI.

- **Two languages, two URLs**: `/` is Italian (`index.html`), `/en/` is English (`en/index.html`),
  generated by `tools/build-en.mjs` — edit only the Italian source, then rerun the generator.
- Bookings + availability calendar + admin panel; Firebase Hosting; GitHub Actions auto-deploys on
  push to `main`.
- Firebase project: `villa-serenita-san-teodoro`.
- SEO: canonical + `hreflang`, Open Graph/Twitter cards, `VacationRental` JSON-LD, `robots.txt`,
  `sitemap.xml`. Full audit + the owner's action list: `docs/seo-marketing-review.md`.

## Layout

- `index.html` — public landing page, **Italian, single source of truth for the markup**.
- `en/index.html` — English page, generated (never hand-edit; it gets overwritten).
- `admin.html` — admin dashboard (login, reservations, calendar; `noindex`).
- `css/` — `style.css` (design tokens + sections 1–17, then 18 "modern refresh" and 19 "visual
  redesign" appended as override layers), `admin.css`, `admin-popup.css`, `calendar.css`.
- `js/` — `firebase-config.js` (init/exports `db`+`auth`), `app.js` (reveal-on-scroll via
  IntersectionObserver, navbar, sticky booking bar, counters, lightbox), `reservations.js`
  (booking form → Firestore), `calendar.js` (Flatpickr availability), `admin.js` (auth,
  reservation CRUD, calendar management), `day-state.js`.
- `tools/` — `build-en.mjs` (generates `/en/` and asserts parity), `check-seo.mjs` (SEO/structural
  gate), `optimize-images.py` (OG image + apple-touch-icon).
- `firestore.rules` + `firestore.indexes.json` — the only server-side layer.
- `DEV_NOTES.md` — developer guide (read before structural changes).
- `docs/seo-marketing-review.md` — audit, measured before/after, keyword plan, owner actions.
- `task/` — payload JSON fixtures; `images/` — assets.

## How to verify (real commands)

```bash
python3 -m http.server 8099      # then open / and /en/
node tools/build-en.mjs          # regenerate en/index.html after ANY index.html edit
node tools/check-seo.mjs         # 55 assertions; non-zero exit on drift (the de-facto test suite)
node --input-type=module --check < js/app.js   # syntax-check a module

# deploy the site (Actions does this on push to main)
firebase deploy --only hosting

# rules/indexes changes are a SEPARATE deploy
firebase deploy --only firestore:rules
firebase deploy --only firestore:indexes
```

No test framework: verification means `check-seo.mjs` plus exercising the flow you touched in a
browser (booking form, admin login, calendar, sticky bar, both language pages) and the console.

## Conventions and gotchas

- **No Cloud Functions**: Firestore security rules are the entire server-side enforcement — never
  rely on client-side checks for an invariant (double bookings, restricted writes).
- **Every user-facing string exists twice** (`<span class="it">` + `<span class="en">`); the active
  language is driven by `body.lang-en`, which `reservations.js`/`calendar.js` read at runtime.
  `data-alt-en` / `data-placeholder-en` are the English twins the generator swaps.
- New image → add `data-alt-en` next to `alt`, then rerun `tools/build-en.mjs`.
- Asset URLs must stay root-absolute in generated pages (`/css/…`): relative ones resolve under
  `/en/` and the page loads unstyled.
- Edits go through a **branch + PR** (never push directly to `main`); the PR gets a Firebase preview.
- `serviceAccountKey.json` and `.env`-style files must never be committed.
- Google masks API keys in API responses (`AIza...xx`) — the web SDK still works on Hosting; don't
  "fix" a masked key.
- Keep `firestore.rules` in sync with what the JS actually writes; a rule change needs its own deploy.
- `firebase.json` `hosting.ignore` keeps `docs/`, `tools/`, `task/`, `test-*`, `*.md` and `villa/` out
  of the deploy — anything new at the repo root is published publicly unless listed there.
- The sticky booking bar rate is hard-coded twice (`index.html` bar + the Low Season pricing card):
  update both.
