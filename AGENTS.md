# VillaST

## What this is

Static website for a vacation rental (Rifugio Tavolara) in San Teodoro, Sardinia: marketing page
plus an integrated booking system with an admin dashboard. **No build step at deploy time** —
HTML5 + CSS3 + vanilla JS ES modules loaded from CDN, with Firebase (Firestore + Auth) as the only
backend. One generated file (`en/index.html`) is committed, never built in CI.

- **Two languages, two URLs**: `/` is Italian (`index.html`), `/en/` is English (`en/index.html`),
  generated by `tools/build-en.mjs` — edit only the Italian source, then rerun the generator.
- Bookings + availability calendar + admin panel; Firebase Hosting; GitHub Actions deploys on push to
  `main`, but **only for changes that can change the deploy**: both workflow triggers carry the same
  `paths-ignore` (`**.md`, `docs/**`, `tools/**`, `test/**`, `villa/**`, `package.json`), so a
  docs-only branch or PR runs no Action at all.
- The host (non-technical, phone-first) runs the rental from `/admin`: one push notification per new
  request (FCM web push to the PWA installed from Safari), accept/decline in two taps, and the
  guest's confirmation email sent from the villa Gmail by a Google Apps Script notifier — free tier,
  no Cloud Functions, no Blaze plan. Email text + villa facts live in `mailSubject_`/`mailHtml_` +
  the `VILLA_` constants of that script; pushes are rendered by the browser from the payload, never
  re-displayed in `sw.js` (a second display path duplicates every notification).
  Setup: `tools/apps-script/README.md`; design + flows:
  `docs/admin-panel-v4-design.md`; rules suite: `test/rules.test.mjs`.
- Firebase project: `villa-serenita-san-teodoro`.
- SEO: canonical + `hreflang`, Open Graph/Twitter cards, `VacationRental` JSON-LD, `robots.txt`,
  `sitemap.xml`. Full audit + the owner's action list: `docs/seo-marketing-review.md`.

## Layout

- `index.html` — public landing page, **Italian, single source of truth for the markup**.
- `en/index.html` — English page, generated (never hand-edit; it gets overwritten).
- `admin.html` — admin panel (login; panels Richieste/Calendario/Prenotazioni/Impostazioni;
  `noindex`). Bottom tab bar on phones, sidebar on desktop.
- `manifest.webmanifest` + `sw.js` — installable PWA for `/admin`. The service worker is push-only
  (no fetch handler, caches nothing) so the public site behaves exactly as without it.
- `css/` — `style.css` (design tokens + sections 1–17, then 18 "modern refresh" and 19 "visual
  redesign" appended as override layers), `admin.css` (v4 light "Casa" theme), `calendar.css`
  (guest Mediterranean + admin light theme).
- `js/` — `firebase-config.js` (init/exports `db`+`auth`), `app.js` (reveal-on-scroll via
  IntersectionObserver, navbar, sticky booking bar, counters, lightbox), `reservations.js`
  (booking form → Firestore; writes `lang` + `pushState`), `calendar.js` (Flatpickr; admin uses the
  Italian `ADMIN_LOCALE`), `day-state.js`, `admin.js` (auth, request queue, CRUD, day sheet),
  `notify-client.js` (FCM token registration).
- `tools/` — `build-en.mjs` (generates `/en/` and asserts parity), `check-seo.mjs` (SEO/structural
  gate), `optimize-images.py` (OG image + apple-touch-icon), `apps-script/` (notifier source +
  deploy checklist).
- `test/rules.test.mjs` — Firestore rules suite (REST against the emulator, no npm deps).
- `firestore.rules` + `firestore.indexes.json` — the only server-side layer; admin access = an
  `admins/{uid}` document.
- `DEV_NOTES.md` — developer guide (read before structural changes).
- `docs/seo-marketing-review.md` — audit, measured before/after, keyword plan, owner actions.
- `docs/admin-panel-v4-design.md` — admin panel v4 design (goals, criteria, flows, manual setup).
- `task/` — payload JSON fixtures; `images/` — assets (incl. the PWA icons).

## How to verify (real commands)

```bash
python3 -m http.server 8099      # then open / and /en/
node tools/build-en.mjs          # regenerate en/index.html after ANY index.html edit
node tools/check-seo.mjs         # 55 assertions; non-zero exit on drift (the de-facto test suite)
node --input-type=module --check < js/app.js   # syntax-check a module

# Firestore rules (port 8081 — see firebase.json "emulators"; 8080 is taken on this host)
npx -y firebase-tools@latest emulators:exec --only firestore --project demo-villast "node test/rules.test.mjs"

# deploy the site (Actions does this on push to main; docs-only pushes are filtered out)
firebase deploy --only hosting

# rules/indexes changes are a SEPARATE deploy
firebase deploy --only firestore:rules
firebase deploy --only firestore:indexes
```

No test framework: verification means `check-seo.mjs` plus exercising the flow you touched in a
browser (booking form, admin login, calendar, sticky bar, both language pages) and the console.

## Conventions and gotchas

- **No Cloud Functions**: Firestore security rules are the entire server-side enforcement for the
  site — never rely on client-side checks for an invariant (double bookings, restricted writes).
  The only out-of-band component is the Apps Script notifier (`tools/apps-script/`), which runs as a
  privileged service account and holds no invariants.
- Admin access = a document at `admins/{uid}` (checked by `firestore.rules`); the panel shows the uid
  under Impostazioni so it can be created once from the Firebase console.
- **Discovery and decision material never enters this repo.** The repo holds shipped artifacts and
  durable user-facing docs (`README.md`, `DEV_NOTES.md`, `docs/vision.md`, design docs for shipped
  work). Option comparisons, cost/risk research, business plans and "what should we do" documents
  live outside it, under `~/.hermes/plans/` (private), delivered via chat/Telegram; once a decision
  lands, only the outcome is committed here.
- **Every user-facing string exists twice** (`<span class="it">` + `<span class="en">`); the active
  language is driven by `body.lang-en`, which `reservations.js`/`calendar.js` read at runtime.
  `data-alt-en` / `data-placeholder-en` are the English twins the generator swaps.
- New image → add `data-alt-en` next to `alt`, then rerun `tools/build-en.mjs`.
- Asset URLs must stay root-absolute in generated pages (`/css/…`): relative ones resolve under
  `/en/` and the page loads unstyled.
- Edits go through a **branch + PR** (never push directly to `main`); a PR that touches deployable
  files gets a Firebase preview channel, while a docs-only PR runs no Action at all.
- `serviceAccountKey.json` and `.env`-style files must never be committed.
- Google masks API keys in API responses (`AIza...xx`) — the web SDK still works on Hosting; don't
  "fix" a masked key.
- Keep `firestore.rules` in sync with what the JS actually writes; a rule change needs its own deploy.
- `firebase.json` `hosting.ignore` keeps `docs/`, `tools/`, `task/`, `test-*`, `*.md` and `villa/` out
  of the deploy — anything new at the repo root is published publicly unless listed there. The same
  six patterns are the `paths-ignore` filter of both `.github/workflows/firebase-hosting-*.yml`
  triggers, so keep the two lists in sync when a new non-deployed path appears.
- The sticky booking bar rate is hard-coded twice (`index.html` bar + the Low Season pricing card):
  update both.
