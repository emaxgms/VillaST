# VillaST — SEO & marketing review

_Reviewed and implemented on branch `feat/seo-redesign-modern`. All numbers below were
measured on this machine (Chromium, `python3 -m http.server`, cache disabled), not estimated._

## TL;DR

The site was invisible to search on purpose-built grounds: one mixed-language URL, no
canonical/hreflang, no structured data, no sitemap, no robots.txt, no social preview, an
H1 that said only the brand, and two contact paths that were dead (placeholder WhatsApp
number, `info@rifugiotavolara.it` on a domain that does not resolve). None of that is a
content problem — the property data was fine. It is now fixed, plus a visual refresh aimed
at conversion: sticky price bar, glass surfaces, one-URL-per-language, FAQ for long-tail
queries.

**Blocking before this is worth anything in Google:** real WhatsApp number + email,
Search Console verification, sitemap submission, Google Business Profile. See
[Owner actions](#owner-actions-required).

## What this PR implements

### 1. One URL per language (`/` = IT, `/en/` = EN)
- `en/index.html` is generated from `index.html` by `tools/build-en.mjs` and **committed**, so
  hosting still has no build step. The generator strips the other language's elements (the
  English page ships a genuinely monolingual DOM, tighter `alt` text and EN placeholders),
  swaps `<html lang>`, title/description, OG tags and the JSON-LD, and rewrites asset paths
  root-absolute (`/css/…`, `/images/…`) — without that, `/en/` loaded unstyled.
- `rel=canonical` + `hreflang` (`it`, `en`, `x-default`) on both pages, mirrored in
  `sitemap.xml` as `xhtml:link` alternates.
- Nav language control is now a real link to the other URL; `localStorage` and the
  `data-placeholder-*` runtime swap are gone. `body.lang-en` still drives the existing
  language CSS, so `js/reservations.js` and `js/calendar.js` needed no change.

### 2. Search metadata
- Titles now carry the intent: `Casa Vacanze San Teodoro, Sardegna — Rifugio Tavolara` /
  `Holiday Rental in San Teodoro, Sardinia — Rifugio Tavolara`.
- Descriptions name capacity, garden, parking and Cala d'Ambra plus a direct-booking CTA.
- H1 keeps the brand but the keyword line ("Casa vacanze a San Teodoro · Sardegna") now lives
  inside it, styled as the existing eyebrow — same design, real keywords.
- OG/Twitter card with a generated `images/og-image.jpg` (1200×630) and `og:locale`.
- `favicon.svg` + `apple-touch-icon.png` (generated by `tools/optimize-images.py`).
- `robots.txt` (admin disallowed) and `sitemap.xml` (both URLs, alternates, x-default).
- `admin.html` is `noindex, nofollow`.
- Deploy hygiene: `firebase.json` now ignores `docs/`, `tools/`, `task/`, `test-*.html`,
  `**/*.md`, `package.json`, `.github/**`, and those scratch files are git-ignored too — they
  were all being published at the site root.

### 3. Structured data
`VacationRental` JSON-LD (in both pages, `inLanguage` and `url` per language): name,
description, CIN `IT090092C2000S4969`, postal address, geo coordinates, check-in/out times,
price range, capacity/bedrooms/bathrooms/floor size and `amenityFeature` list — every value
taken from the site's own verified content.

### 4. Performance
- AOS removed (2 CDN requests + a scroll-linked library) → native `IntersectionObserver`
  reveal, `data-aos*` markup unchanged. First load: **21 → 17 requests, 12 → 8 third-party**,
  DOMContentLoaded 491 → 432 ms (local, uncached).
- Hero `<img>` gets `fetchpriority` + a matching `<link rel=preload>`; Flatpickr is `defer`red.
- All content images carry `width`/`height` (CLS) and `decoding="async"`.
- The lightbox's 55 lines of inline-injected CSS moved into `css/style.css` (cacheable,
  editable) and the lightbox regained focus management.
- Cache-Control headers for images (1 year) and css/js (1 hour).

### 5. Conversion + modern feel
- **Sticky booking bar**: price "da €80/notte" + "Verifica disponibilità", appears once the
  hero is scrolled past, parks itself while the booking form or footer (WhatsApp CTA) is on
  screen. Mirrors the Low Season rate in `#pricing` — keep the two in sync.
- Glass navigation (`backdrop-filter` + saturate) and glass sticky bar.
- Cinematic hero: Ken Burns still (the keyframes existed, unused).
- Denser 6-column gallery bento at ≥1024 px (14 tiles, `grid-auto-flow: dense`, verified to
  produce 5 rows with zero overlaps and no holes).
- FAQ section: 7 real questions/answers (beach distances, check-in/out, capacity, parking,
  linen, pets, payment) — long-tail landing content plus an anchor link in both navs.
- Mobile nav bug fixed: below 400 px the desktop links overflowed 84 px; the nav now collapses
  to the burger at all phone widths.

The one structural content gap left: there is no page for the *destination* intent
("cosa fare a San Teodoro", "spiagge di San Teodoro"), which is where the blog-level traffic
that eventually converts lives. A single `/guide/` (+ `/en/guide/`) page with internal links
to the booking form is the cheapest next win — it needs real local copy, so it is **not**
fabricated here.

## Off-page / channel plan

- **Reviews first.** 9.3 with 3 reviews is your best asset and the current blocker: Booking
  reports → one follow-up message per stay, ask for a Google review too (feeds the GBP score,
  which is what locals see first). 15+ Google reviews changes local rankings more than any
  on-page tweak.
- **Direct-booking incentive.** The site promises a best-price guarantee but Booking.com is
  still the default path. Make the direct offer explicit: "same price as Booking.com, host
  contact, no platform fees" + a repeat-guest discount code for the WhatsApp channel.
- **Seasonal campaigns.** July–August minimum 5 nights, shoulder May/June and September —
  the mid-season card is priced at €120; the shoulder months are where direct bookings can be
  won with a "settimana al mare" package.
- **Local partnerships.** San Teodoro restaurants listed on the page (Il Salsero, Food Lab,
  Griglieria Lo Sfizio are within 300 m) are natural link/cross-promo partners.
- **Channels worth the time, in order:** Google Business Profile posts, Instagram (beach +
  garden reel, seasonal), Booking.com listing optimisation, Sardinian tourism directories
  (link + referral traffic), then paid — only once analytics exist.

## Deliberately NOT done (with the reasons)

- **WebP/AVIF twins.** Measured on the actual sources: 1.47 MB → 1.34 MB at q80 (−9 %) and
  1.08 MB at q62 (−26 %). The photos are already heavily compressed Booking.com exports, so
  the saving does not justify either the quality risk or `<picture>` markup everywhere. The
  real fix is reshooting at 2×; `tools/optimize-images.py` documents this.
- **`aggregateRating` markup.** The 9.3 comes from Booking.com. Marking up reviews collected
  elsewhere violates Google's review-snippet policy; the visual badge stays, the markup does not.
- **`FAQPage` markup.** Google restricted FAQ rich results to authoritative government/health
  sites — the FAQ earns its keep as content and as an anchor, not as a rich result.
- **Splitting fonts / self-hosting them.** Two families (Cormorant Garamond, Jost) with
  existing weights are kept to avoid a visual regression; worth revisiting only with a font
  subsetting pass and a real before/after measurement.
- **A build step.** The generator stays manual with committed output: no CI/CD change, no
  surprise deploy failures, and `tools/check-seo.mjs` fails loudly if it is forgotten.
- **`/guide/` destination content.** Needs genuine local copy (see above).
